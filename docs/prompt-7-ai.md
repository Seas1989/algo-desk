# 提示词 7｜接入 AI 分析（BYOK，无后端）

> 等前六条稳定、`npm run build` 连续通过之后再贴。
> **前置依赖：任务 6 必须先完成。** 否则访客看到的永远是站主那份静态数据，AI 分析的
> 是别人的成绩，没有意义。

## 设计前提（别让 AI 自由发挥）

静态站点没有后端，所以只能走 **BYOK（Bring Your Own Key）**：

- 访客在设置面板里填自己的 API 地址 + Key + 模型名
- Key 只存在浏览器 `localStorage`，直连服务商，不经过任何中间服务器
- 兼容 OpenAI 协议（`POST {baseURL}/chat/completions`），这样一份代码能吃下
  DeepSeek、硅基流动、通义、智谱、OpenRouter、本地 Ollama

## 提示词

```
给站点加一个 AI 分析面板。没有后端，走 BYOK：访客填自己的 API Key，浏览器直连服务商。

【前置】必须已有「按 handle 查自己」的能力（?cf=xxx）。没有的话先停下，告诉我。

【1. 设置】
src/settings.js 新建（没有就建），存三样东西到 localStorage["algodesk.ai"]：
  { baseURL, apiKey, model }
提供预设下拉，切换时自动填 baseURL 和默认模型：
  DeepSeek      https://api.deepseek.com/v1                 deepseek-chat
  硅基流动       https://api.siliconflow.cn/v1                Qwen/Qwen2.5-7B-Instruct
  通义千问       https://dashscope.aliyuncs.com/compatible-mode/v1  qwen-plus
  智谱          https://open.bigmodel.cn/api/paas/v4          glm-4-flash
  OpenRouter    https://openrouter.ai/api/v1                 deepseek/deepseek-chat
  自定义        空                                         空
界面上明确写一句：Key 只保存在这台设备的浏览器里，不会上传到任何服务器。

【2. 上下文构建器】src/ai-context.js 新建
不要塞整个 cf.json（200KB+）。写 buildContext()，产出 800 字以内的纯文本摘要，包含：
- 当前用户：CF handle、积分、最高分、已过题数；洛谷 uid、积分、通过数
- 欠账：比赛未完成 N 道、洛谷未通过 M 道
- 薄弱标签：按未完成数取前 8 个，带「未过 / 已过」两个数字
- 当前正在看的题（如果从某道题点进面板）：题号、题名、难度、标签、提交次数、最后评测结果
- 最近 5 场比赛：名称、rank、积分变化、过题数/总题数
- 未完成题清单：只取难度最低的 15 道，写成「2254C 1000 贪心 提交2次」
所有数字都要真实来自现有 JSON，不许占位。

【3. 面板 UI】
- 右下角浮动按钮，点开右侧抽屉（宽 400，窄屏全宽）
- 消息流：用户右侧、AI 左侧；等回复时显示三点动画
- 底部输入框 + 发送；Enter 发送，Shift+Enter 换行
- 四个快捷指令按钮，点了直接填好并发送：
  「解释这道题」「给我今天的计划」「我卡在哪」「推荐 3 道同类型的题」
- 「清空对话」「设置」两个次要入口

【4. 请求】
- POST `${baseURL}/chat/completions`，body：model、messages、temperature 0.3、max_tokens 800
- messages = 一条 system + 上下文 + 历史对话（只保留最近 6 轮，避免超长）
- system 提示词要点（照抄）：
  「你是算法竞赛教练。只依据下面给出的数据回答，数据里没有的题目不要编造。
    给建议时要具体到题号和做法方向，不要泛泛而谈。
    不确定就直说信息不足。中文回答，控制在 200 字以内。」
- 先做非流式，拿到完整回复再渲染；代码里留一行注释说明后续可换 SSE 流式

【5. 错误处理】
- 没配 Key：面板里显示配置引导，不发起请求
- 401 / 403：提示「Key 无效或无权限」
- 429：提示「触发限流，稍后再试」
- 网络错误：提示「连不上，检查 API 地址」
- 所有报错都显示在消息流里，不要弹 alert、不要白屏

【6. 隐私】
- 请求体里只能出现：公开统计数据、题号题名、标签、比赛名
- 绝不能出现账号密码、Cookie、localStorage 里的其他内容
- 面板底部用小字写：分析基于你的公开提交数据，不包含账号凭据

【约束】不引入依赖，用原生 fetch；不引入后端；不把 Key 写进 URL 或 console.log。
【验收】npm run build 通过；不填 Key 时面板给出引导；填入一个真实 Key 后
「解释这道题」能返回和当前题相关的中文回答；断网/错 Key 时错误提示准确不白屏。
```

## 为什么这么设计

**为什么必须 BYOK**：静态站点没有后端，任何「内置免费额度」要么需要服务器代理，
要么就是把别人家的 Key 硬编码进前端——后者等于公开泄露。BYOK 是唯一既不用后端、
又不需要你去付账的方案。

**为什么要「前置任务 6」**：AI 要分析得准，前提是它拿到的数据属于**当前看页面的人**。
现在站点只有你一个人的静态快照，别人打开看到的是你的成绩，问 AI「我该练什么」
它只能分析你。所以先有 `?cf=handle`，AI 才有意义。

**为什么上下文要压缩到 800 字**：`cf.json` 有 223 KB，直接塞进去会瞬间吃掉几万 token，
又慢又贵，还会让模型抓不住重点。只喂「欠账数 + 薄弱标签 + 最低难度的 15 道题 + 当前题」
这一小撮，分析反而更准。

**为什么要写死 system 提示词**：不约束的话，模型会开始编题号、编 title、给「多刷题」
这种正确的废话。限定「只依据给定数据、具体到题号、不超 200 字」，输出才能直接用。
